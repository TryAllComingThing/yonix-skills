# Presentation Profile V1.4
专业场景配置，不是用户画像。选择一个主场景，辅助场景仅补足主场景缺口；冲突按当前受众决策目标解决。不得固定页数、颜色或虚构事实。方法引用 knowledge 与 patterns，不复制其规则。
| ID / 场景 | 受众与决策 | 内容与叙事 | 深度及图解 | 证据与反例 |
|---|---|---|---|---|
| S01 产品介绍 | 使用者理解是否适用 | 定位→能力→场景→体验→行动 | 功能地图、操作流程；说明边界 | 实际功能与截图；不把路线图当现状 |
| S02 客户汇报 | 客户判断匹配与合作 | 痛点→匹配→演示→差距→价值 | 业务闭环、价值链；明确未覆盖需求 | 客户授权事实；不虚构收益 |
| S03 行业方案 | 行业负责人判断适配 | 行业问题→业务闭环→方案→实施 | 业务架构、场景与数据关系 | 行业来源及适用条件；不泛化案例 |
| S04 建设方案 | 领导及技术负责人判断可实施 | 目标→范围→功能→架构→实施→验收 | 模块协作、关键机制、边界及异常 | 权威方案与候选区分；不只罗列功能 |
| S05 技术交流 | 技术评审者判断取舍 | 约束→机制→选型→风险→验证 | 分层架构、时序、异常路径 | 测试证据与未验证项；不以术语代机制 |
| S06 领导汇报 | 决策者判断是否批准 | 必要性→方案→价值→风险→决策 | 决策对比、路线图；技术细节按需附录 | 投入和收益来源；不伪造数字 |
| S07 成果验收 | 验收者判断达标 | 目标→实际交付→证据→差距→后续 | 指标对照、交付映射 | 实测证据；不将计划当成果 |
| S08 企业能力 | 客户判断合作可信度 | 能力体系→产品→案例→服务→合作 | 能力地图、服务路线 | 可披露案例及实际能力；不夸大 |
主辅示例：S04+S06，保留建设范围和机制，增加决策与风险，细节按时长调整。S08+S03+S02，企业能力主线，行业场景和客户匹配作为补充。
