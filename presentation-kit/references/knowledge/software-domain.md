# 软件领域专业设计
先建立目标—角色—场景—业务规则—能力—功能—数据—接口—部署追踪链。区分业务架构（业务域与协同）、功能架构（功能归属）、系统架构（组件边界与依赖）、部署架构（运行节点与网络）。
L1 继承权威资料；L2 补齐必要场景、异常与约束；L3 提出候选方案及取舍，重大新增决策须确认。按内容选择，不机械整篇深化。
需求分析覆盖角色、触发、前置、主流程、异常、结果、权限、数据生命周期。技术设计覆盖接口协议、事务一致性、幂等、故障恢复、可观测性、安全及容量假设；只展示与汇报目的相关的内容。
资料优先级：当前确认决策、权威设计、产品资料、其他参考。冲突显式登记。截图只证明可观察界面；PRD 只证明需求；运行和性能需要独立证据。


## 专业推导操作
逐项建立事实ID、来源位置、状态、业务规则、受影响页面。PRD-only 先识别对象与生命周期，再推导功能、权限、异常和接口；将新增设计标 L2/L3。例：不可变表单版本意味着历史填报关联原版本，不能用最新模板覆盖。技术汇报区分控制面、数据面、运行拓扑；对事务、重试、撤权分别给出正常与失败路径。验收：每个核心能力能回溯需求，新增决策有批准记录。
