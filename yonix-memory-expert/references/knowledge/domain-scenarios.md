# Domain and scenario extraction guide
Domain describes work, topic describes subject, scenario describes purpose/audience. Classify by deliverable and goal, not keyword alone. Multi-domain tasks select relevant entries without duplication. Examples below are methods, not user data.
| Domain | Scenario | Extract | Do not infer |
|---|---|---|---|
| product-design | discovery | problem framing, prioritization, decision style | product scope as global preference |
| product-design | PRD | rule depth, exceptions, acceptance, traceability | every feature is required elsewhere |
| product-design | prototype | interaction, layout, accessibility | one screenshot is universal style |
| solution-design | industry solution | business value, industry evidence, implementation | client facts as personal memory |
| solution-design | technical construction | mechanisms, module collaboration, reliability | architecture choice universal |
| solution-design | initiation | cost, risk, scope tradeoffs | approved budget as preference |
| presentation | customer | audience pain, value, narrative, case evidence | invented customer outcomes |
| presentation | leadership | decision, concise summary, risk | all documents short |
| presentation | technical | architecture diagrams, technical depth | all decks dense |
| presentation | capability | differentiators, services, evidence | unverified capability |
| document-writing | technical | sections, terminology, depth, versioning | current template permanent |
| document-writing | tender | compliance, response, implementation | confidential bid content |
| document-writing | report | findings, action, evidence | one report structure universal |
| research-analysis | industry | source quality, time window, method | source claims as user beliefs |
| research-analysis | comparison | criteria, tradeoffs, evidence | chosen vendor permanent |
| research-analysis | review | severity, evidence, actionable remediation | simulated experts real |
| learning | plan | baseline, goal, materials, pace | learning topic as expertise |
| learning | practice | budget, examples, exercises, acceptance | temporary budget universal |
## Cross-cutting examples
AI industrial solution: solution-design primary, research-analysis secondary, topic AI/manufacturing. Customer presentation of same solution: presentation primary. Robotics study: learning primary. For each, capture only durable user preferences, not task data. When a domain is absent, use relevant global memory and proceed; do not fabricate a profile. New domains need explicit sustained relevance, not a directory for each Skill.

## Presentation scenario refinement
Product introduction: experience and capability boundaries; customer: pain/value/match; industry solution: business loop and evidence; construction: scope/mechanism/implementation; technical: tradeoffs and exceptions; leadership: decisions/risk; acceptance: evidence and gaps; enterprise capability: differentiation/services. Extract durable user choices only, not professional defaults or current page edits. Multiple scenarios may coexist; do not broaden scope.
