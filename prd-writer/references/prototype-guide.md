# PRD 到原型的交接

## 交接范围

有 [PRD 模板](prd-template.md) §9.2 或等价交接明细时，按明细确定本轮范围、实现方式和就绪状态。优先用 §0.2 定位入口，缺摘要时从正文定位并记录出处。沿用项目优先级。已有 PRD 无交接表时，按用户指定范围、章节语义及稳定编号定位页面、动作、事件和验收，记录派生依据。

| 路径 | 交接信息 |
|---|---|
| 界面 | F、P、A 或稳定控件位置、AC，附角色、入口、前置状态、成功／失败反馈、返回和数据变化 |
| 纯后台 | F、事件、状态、副作用、观察入口和 AC |
| Mock | 固定样例、初态、响应、终态、副作用及重置，标记模拟范围 |
| 待决 | D 编号、双方出处或缺口、受阻环节和可继续范围 |

关键规则有明确出处且无冲突的草案路径可用于评审预览，标明草案状态。高影响待决仅按第 08 章的策略展示标记或阻断操作。需要正式交接时，记录业务确认依据。

## 下游验收

由 `prd-prototype` 生成或更新独立离线 HTML 原型，并在 `acceptance.md` 中记录实际入口、版本、范围、前置、动作、预期和结果。按实际页面、动作或事件核对覆盖。页面、控件或事件标识可作为定位依据。浏览器实测、Mock 和真实联调分别记录，保留未运行和受阻状态。

## 设计规范与交付形态

沿用项目设计规范、已有组件和图标库。

独立 HTML 使用本地资源，由原型交付方实测离线入口。PRD 记录适用的视觉、交互和项目技术约束，关联页面、动作及验收。
