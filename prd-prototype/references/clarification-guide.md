# 关键缺口与来源冲突

只处理会改变本轮范围、关键业务行为或验收的缺口。已有明确依据的局部修订直接推进。对照用户指定的 PRD、现有原型与已确认决策。记录冲突双方的版本、章节和受影响的动作或 AC。

| 情况 | 处理 |
|---|---|
| 本轮明确变更 | 按指定范围执行，核对直接受影响的规则、路由、状态及验收 |
| 有据且无冲突的草案 | 标明草案状态，继续制作相关评审预览 |
| 权限、金额、不可逆动作或未知执行结果缺规则 | 保留原待决编号或分配可定位标识，标出受阻动作和验收。可继续的独立路径照常交付 |
| 可逆的展示细节缺省 | 优先采用项目组件和设计约定。有必要时记录采用的默认值 |
| 需用户裁决 | 说明可选项、依据和实际影响，集中询问仍阻断交付的关键问题 |

对受阻路径沿用 PRD 的只读示意或阻断约定。说明尚需确认的内容，保留已有草案和证据。已有 PRD 以其交接契约为准。需要先写 PRD 的组合任务交给宿主可用的写作能力处理。
