# 可交互原型实现

## 交付范围

按 [PRD 输入交接](prd-intake.md) 建立映射。逐项实现纳入且可制作的页面、动作或系统事件，保留范围外、只读和受阻条目的标识。PRD 允许只读示意时，标明待决依据并保持相关动作不可执行，对应验收仍为受阻。正文决定规则和终态，ASCII 用于布局，Mermaid 用于关键动线。纯后台事件用状态、记录或模拟事件观察点交付。

已有原型的局改以指定版本为起点，只同步受影响页面、路由、组件、状态和验收。沿用用户指定的保真度与项目设计规范。依据充分的草案路径可用于预览，待决按其影响范围隔离。

## 按验证目的确定保真度

沿用用户指定的保真度与目标端。局部修订延续既有视觉和交互约定。未指定且不同保真度会实质影响交付时，制作前用 1～2 句给出建议、理由和本轮重点。意图明确时直接选用适合的方案。仅在关键范围或行为缺少依据时提出具体问题。

例如：「本轮用于内部交互评审，建议沿用现有视觉，重点验证默认筛选、详情返回和筛选恢复。」

| 验证目的 | 实现重点 |
|---|---|
| 信息结构评审 | 还原页面层级、区域和导航，内容细节以支持结构评审为限 |
| 操作与业务评审 | 实现关键动作、分支、反馈、状态恢复和适用的副作用 |
| 客户演示或视觉评审 | 复用项目主题、组件和文案约定，细化本轮演示路径 |
| 多端一致性 | 按指定端和视口验证布局、导航及关键动作 |

各类原型均以本轮交接的验收范围为准。

## 独立离线 HTML

使用 [HTML 骨架](../assets/prototype-template.html) 或现有原型。按实际页面、角色和样例替换所有示例内容和行为。资源随交付包提供，离线入口应可通过 `file://` 打开。已有交互和布局优先复用。可按需参考 [组件库](component-library.md)，项目主题、组件和图标规范优先。

明确默认入口、有效目标、直达或返回策略及适用视口。无效目标保留有效画面并提供反馈。PRD 要求浏览器后退、刷新恢复或直达时，落实相应的 URL、导航及上下文状态并逐项走查。演示面板和状态切换器按需保留，标明演示用途，核心验收走实际交互或模拟事件入口。

## 交互及验收

- 将 PRD 文案、样例字段和用户输入按文本渲染。使用 `textContent` 或文本节点。避免将这些输入拼接为 HTML、脚本、事件处理器或未经验证的链接。演示数据遵循 [输入约定](prd-intake.md#输入与演示数据)。
- 关键动作落实角色、业务键、前置状态、响应、反馈、返回和副作用。导航、表单和弹层核对键盘可达及焦点恢复。
- 模拟按 PRD 约定提供固定数据、响应、终态、计数和重置。权限拒绝检查反馈和数据边界；执行结果未知时沿用已确认的重试规则。
- 页面标注、路由和组件可帮助定位。以实际动作或事件的观察结果判定验收，并按 [验证规范](verification.md) 统一写入 `acceptance.md`。
