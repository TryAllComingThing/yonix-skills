# PRD Prototype

## Trigger｜触发

显式调用 `@prd-prototype`。斜杠调用随宿主支持。用于「按这份 PRD 做交互原型」或「按 PRD 只更新原型某处」。同时要求撰写 PRD 和生成原型时先用宿主可用的 PRD 写作能力（当前环境为 `prd-writer`，旧环境可使用 `prd-write`）形成规格，随即继续实现已有依据的范围。已有 PRD 时直接读取文档。

## Workflow｜执行

1. 按 [PRD 输入](references/prd-intake.md) 读指定版本、设计规范和已有原型，定位范围、规则与验收。仅关键冲突或缺口按 [澄清指导](references/clarification-guide.md) 处理。
2. 依据充分时直接制作或定向修订。复杂场景按需参考 [方法选择](references/method-selector.md) 与 [方法套件](references/method-toolkit.md)。
3. 按 [原型指导](references/prototype-guide.md) 实现。未指定保真度且选择会实质影响交付时，制作前用 1～2 句说明建议和理由。依据充分时直接推进。沿用已有原型的组件和设计规范。按需读 [组件库](references/component-library.md)。独立离线 HTML 可从 [模板](assets/prototype-template.html) 改造，替换全部示例页面、数据和规则。
4. 按 [验证规范](references/verification.md) 打开实际交付物，验证主链、适用异常、返回、状态及副作用，修复后复测。
5. 交付 `acceptance.md`，有产物时附实际入口，并用 1～2 句指明角色或固定样例及主链。产物未生成时记录受阻范围、缺失前提和续做步骤。按需补充异常、受阻项和重置方式。只指引实际提供的状态切换器或走查面板，并注明实测状态和模拟边界。局部修订按需注明改动项、影响路径、回归验收编号和待决项。

## Verification Gates｜交付证据

| 门禁 | 核对实际产物 |
|---|---|
| G1 来源和范围 | PRD 版本或章节、本轮纳入的页面或事件、对应动作／规则／验收编号、受阻项 |
| G2 可运行 | 实际 HTML 运行入口，核心路径和可复现场景 |
| G3 可复核 | 环境、前置、步骤、预期、实测、结果状态和证据位置 |

在验收记录中绑定实际 PRD 和原型基线，变更后按验证规范复核旧证据。浏览器未执行时标未运行。逐条记录验收层和场景。关键用例实际通过后才可标记对应范围模拟走查通过。

## Anti-rationalization Table｜反借口表

| 跳步理由 | 核对动作 |
|---|---|
| 有按钮就完成 | 点击并断言页面、数据或状态变化 |
| 截图正常 | 实际执行主链、返回和关键异常 |
| 套了模板 | 验证交付版本的导航、键盘焦点、状态与控制台 |
| Mock 成功就是联调成功 | 明确模拟边界及真实接口验证状态 |
| 超时就重试 | 核对执行确认、待确认、重试条件和副作用 |
| 写了测试脚本 | 以实际运行结果判定，缺结果标未运行 |

## Red Flag｜风险与验收

记录来源冲突、权限或不可逆副作用规则缺失、死链空屏、核心操作无反馈、超范围真实接口与外网依赖。写明证据、影响和处置。关键待决只阻断相关交互，已确认范围继续。高风险验收同时观察终态及调用、事件或记录等副作用。
