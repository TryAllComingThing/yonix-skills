# V1.0 多角色专家模拟评审与整改决策（2026-11-15）

> 评审性质：基于真实套件文件的 AI 多角色评审；不是外部专家现场参与或签字。P0/P1 是整改优先级，不代表已经在目标产品上复测。

| ID | 专家视角 | 发现（V1.0证据） | 等级 | 修订决策 | 验证 |
|---|---|---|---|---|---|
| R01 | Codex技能架构 | 总入口作为单独 SKILL.md 与四技能分别安装的说明不够一致，分离安装后共享文件相对路径可能失效 | P0 | 总入口作为项目协调文件；四专业技能以完整套件内相对路径引用共享资产；提供项目级整体安装方案 | 路径检查脚本 |
| R02 | QA | `audit_html.py` 只能进行结构扫描，无法检测 JS 语法错误；原文容易把 G0 静态通过解释为完整源码通过 | P0 | 新增可选 Node 内联 JS 语法检查，报告结构与语法分开 | 单测+真实 MaaS 扫描 |
| R03 | QA | HTMLParser 对未闭合 script 和重复动态 ID 的覆盖有限，G0 的 PASS_WITH_WARNINGS 与门禁状态字典不完全统一 | P1 | 增加检查范围说明，标准化 gate_status PASS/FAIL，保留风险 warning；明确静态局限 | 单测 |
| R04 | 产品专家 | 变更单缺少来源权威/冲突决策/用户显式约束/验收豁免，容易产生需求漂移 | P1 | 模板补充权威决策、非目标、风险接受人和验证方法 | 模板核对 |
| R05 | UI/UX | 视觉标准有原则但缺少可执行截图条件与判定口径，无法真正做一致性验收 | P1 | 固定视口/字体/缩放/数据、组件状态与视觉差异分级 | 规范核对 |
| R06 | 前端架构 | 单文件 HTML 覆盖脚本技术债没有可执行收敛策略；禁止追加覆盖不够可操作 | P1 | 增加入口定位、覆盖链、最小修订、收敛与回滚的步骤及止损条件 | 实战案例 |
| R07 | 安全 | 业务数据与演示数据区分已有，但敏感字段泄漏与动态 HTML 注入缺少明确安全检查清单 | P1 | 增加凭证脱敏、HTML注入、外部依赖、权限绕过检查 | 检查清单 |
| R08 | 测试工程 | 原有4条测试偏少，无法证明 CLI 退出码、编码与 Node 检查稳定 | P1 | 扩充单测与命令行烟测；缺失 Node 时标记 NOT_RUN | 测试报告 |
| R09 | 交付经理 | 交付未定义基线指纹、证据路径与可复现命令 | P1 | 交付模板补充 SHA256、命令、环境、基线/产物对应关系 | 清单检查 |

## 结论
V1.0 可作为初始规则集合，但不宜宣称已具备原生 Codex 自动执行和 G2—G4 真实验收能力。V1.1 只修复已发现的可复用能力与质量门禁，不增加第五个专业 Skill，不强制迁移 Vue，也不引入重型依赖。
