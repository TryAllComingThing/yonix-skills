# Prototype Interaction Contracts V1.2

## 1. 页面契约
每个页面定义 `pageId, route, role, task, pattern, dataSource, states, actions, navigation, errors`；每个操作定义 `trigger, guard, input, validation, stateChange, feedback, rollback, audit, tests`。页面标题只出现一次，路由与面包屑一致。

## 2. 通用动作矩阵
| 动作 | 前置条件 | 成功行为 | 失败/边界 | 必测 |
|---|---|---|---|---|
| 新增 | 有创建权限 | 打开空草稿；保存后列表更新 | 必填/重名/重复提交 | 创建→列表→详情 |
| 编辑 | 对象存在且可编辑 | 从当前版本克隆草稿，保存后统一更新 | 并发修改、取消、权限变化 | 取消不污染；保存回显 |
| 删除 | 有权限且无禁止引用 | 确认后移除并修正分页 | 有引用/失败/取消 | 禁止误删、回滚 |
| 启用/禁用 | 状态转换合法 | 更新状态与可用操作 | 受引用保护/失败 | 状态与按钮一致 |
| 查询/重置 | 条件合法 | 列表和总数一致 | 空态/条件变化 | 清空、分页复位 |
| 详情 | 有查看权限 | 只读展示稳定版本 | 不存在/长文本/脱敏 | 关闭、焦点返回 |
| Tab 切换 | 目标 Tab 存在 | 局部更新选中态与内容 | 连续切换/无数据 | ≥3轮不冻结 |
| 发布/应用 | 完成门禁 | 生成独立快照/待回执状态 | 失败保留旧有效配置 | 草稿隔离与回退 |

## 3. Dialog 契约
打开时保存触发点并将焦点置于标题或首个有效控件；关闭时返回触发点；Esc、遮罩点击、关闭按钮策略一致；dirty 表单关闭需确认；标题栏/底部固定、内容区独立滚动；背景不可误操作。宽度由内容与视口约束，不以任意固定像素强撑。

## 4. 表单契约
字段类型、必填、默认值、帮助文案、合法范围、条件显示、错误位置、异步提交、重试、取消、提交中禁用均明确。错误保留用户输入；“保存”只更新保存态，不等于“发布”。

## 5. 跨页面契约
稳定 ID/复合键是关联权威；列表、详情、编辑引用同一 repository/selector；编辑草稿与当前有效态分离；删除被引用对象按显式规则处理；角色权限必须在数据/操作层验证，不能只靠按钮隐藏。

## 6. 状态矩阵
`idle/loading/empty/error/ready/dirty/submitting/success/disabled/unknown` 按页面适用性取子集。对每个状态写可见反馈、可用操作、转移事件、测试。确认操作仅改变确认状态，不应偷偷改变独立的运行/恢复状态。

## 7. 典型反例
- 仅根据显示名称关联对象 → 同名跨组织/端点时串数据。
- 编辑表单直接绑定 store 对象 → 取消后数据已污染。
- Tab 点击调用全站 render → 可能丢焦点、滚动并导致性能阻塞。
- 保存成功就显示已发布 → 没有生效确认依据。
- UI 删除执行资源配置就移除后端容量保护 → 破坏业务边界。
