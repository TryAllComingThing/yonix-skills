# 专家判断方法 V1.3：从原则到可执行决策

## 统一决策记录（所有模式必须使用，轻微修改可简写）
1. **观察**：用户任务、现有页面/源码、截图、设计权威、运行证据；逐条标记已证实/推断/未知。
2. **约束**：角色、业务对象、权限、设备视口、设计系统、性能、交付时间；列不可破坏项。
3. **候选**：至少比较复用现有、扩展现有、建立新模式；避免为了比较而设计无意义方案。
4. **权衡**：按业务正确性 > 用户任务完成 > 可访问性 > 一致性 > 视觉细节 > 实现便利排序；有明确用户要求时遵循要求并报告风险。
5. **决定**：写选择原因、舍弃原因、影响面、回滚点；一项变更对应至少一个可测断言。
6. **反证**：主动寻找空态、错误、取消、重复提交、权限、跨页面引用、窄屏、长文本的失败案例。
7. **证据**：每个结论对应源码/截图/测试输出；缺少工具或环境标记 NOT_RUN/BLOCKED。

## 产品建模：实体 × 生命周期 × 角色任务
- 从用户目标提取业务对象，定义稳定 ID、唯一性、归属、引用关系、生命周期状态。
- 对每个角色列目标任务及允许操作；区分原型可见性与真实授权，不把隐藏按钮等同安全控制。
- 为每个对象遍历：创建、查询、详情、编辑、删除/停用、关联、历史（仅业务必要时），明确 N/A 原因。
- 建立 `页面 → 角色 → 对象 → 动作 → 状态转换 → 测试` 可追溯链。没有业务价值的页面不生成。
- **正例**：管理设备有停用状态且被工单引用，删除前显示引用保护。
- **反例**：因模板包含“审批”就无需求地添加审批中心；因 CRUD 惯例允许删除已被引用的对象。

## UI/UX：模式选择不是组件罗列
- 简单上下文只读详情→Dialog；较长且需要与列表对照→Drawer；深链/多步骤/跨模块→Page；项目冻结规范优先。
- 频繁动作优先显露；低频动作收进更多；危险动作与其他操作隔离并提供后果说明。
- 表格宽度：先计算固定列、操作列、内边距，再分配弹性列；不足时选择列裁剪/横向滚动/响应式卡片，不能直接溢出。
- **正例**：窄视口将低频操作折叠，保留主要操作文本；筛选条件跨分页保持。
- **反例**：仅靠 `overflow:hidden` 裁切按钮；删除 Tabs 时顺便删掉唯一的业务能力入口。

## 视觉：按影响排序而非像素盲调
- 截图还原先识别信息结构、容器宽高、对齐/密度、排版，再颜色、边框、阴影、图标。
- 差异优先级：关键操作不可见/遮挡(P0) > 结构错位或文本截断(P1) > 色彩和装饰偏差(P2)。
- 固定 viewport、DPR、字体、主题、Mock seed、滚动位置与浏览器版本；没有同条件基线时只可报告观察，不能给出量化相似度。
- **正例**：先复用项目 CSS tokens 与 Dialog shell，再局部覆盖内容栅格。
- **反例**：为一个截图引入新的全局颜色覆盖，破坏其他主题。

## 前端：复用决策
- 已有组件满足语义/状态/可访问性契约→复用；可兼容扩展→扩展并回归；至少两处稳定重复→抽公共模块；业务语义不同→保持专用。
- 数据状态分为服务端模拟权威状态、草稿编辑状态、视图局部状态；取消只丢弃草稿，发布只读取明确快照。
- 禁止通过新增全局 render 覆盖掩盖原实现；先定位唯一入口及依赖链，原位修改并删除死代码需有回归证据。
- **正例**：两个详情复用 `InfoGrid`，但不同业务状态独立；共享稳定 ID。
- **反例**：用名称连接不同端点模型；为每个弹窗复制一套 CSS；编辑草稿直接改变已发布配置。
