# Mock Data & State Design V1.2

## 目标与边界
Mock 的目的：演示业务规则与交互结果，保证数据关系一致、可重置、可回放；不伪造真实 API、推理、监控或发布回执。开发态数据必须明显区别生产数据。

## 1. 数据分层
`seed fixtures → mock repository → domain actions/guards → selectors → views`。每层只承担一类责任；禁止每个页面独立维护同一对象的复制品。Mock repository 提供 `list/get/create/update/delete/reset`，跨页由共享 ID 关联。

## 2. 稳定主键与关系
- `id` 永不依赖显示名；同名对象可存在不同租户/端点/作用域。
- 关联关系显式 `parentId`, `resourceId`, `modelRef={endpointId,modelId,version}` 等；模型复合键仅为 MaaS 案例，不强制其它系统使用。
- 删除/停用前检查引用；不存在引用的处理规则不能自动猜测。
- 版本变更必须可见，旧快照引用固定版本；变更后的候选数据不应原位污染历史记录。

## 3. 原型状态机
`draft → saved → pending_apply → active`，失败可 `apply_failed` 并保留先前 active；这是**示例状态机**，实际由业务设计确认。`editingDraft` 为副本，取消直接丢弃；提交中禁用重复点击；Mock 延迟/失败注入应可配置并可复现。

## 4. Mock 演示样本
至少覆盖：正常记录、同名不同 ID、无关联、已关联不可删除、禁用状态、超长文本、空列表、边界数值、模拟失败、待确认状态。避免用随机数导致截图/测试不稳定；时间用固定基准或注入 clock。

## 5. 持久化策略
默认内存态、刷新重置；如使用 localStorage 明确数据范围、版本迁移、重置按钮及隐私限制。不要在 localStorage 放真实密钥；敏感字段脱敏，前端不存生产凭证。

## 6. 跨页回归示例
1. 列表编辑 A，取消后详情仍旧值。
2. 编辑 A 保存，列表/详情/关联页同一值。
3. 创建同名不同 ID 的 A/B，选择 B 不得串到 A。
4. 已发布版本 S1，修改草稿 D2，S1 快照保持不可变；应用失败仍显示 S1 生效。
5. 删除有引用的对象被阻断并解释影响。
6. `reset()` 后恢复 seed，所有演示步骤可重复。

## 7. Mock 交付契约
记录 seed 版本、实体关系图、状态转移表、演示脚本、错误注入方法、重置方式与未模拟的后端能力。Mock 成功状态必须标识为“模拟”。
