# MaaS 管理平台原型复盘（通用能力蒸馏示例）

> 这是历史原型案例，不是所有企业管理平台必须采用的业务设计。详细证据需回到实际源码和测试。

| 历史症状 | 通用根因假设 | 抽象的专家能力 | 建议验收 |
|---|---|---|---|
| 详情重复标题/操作 | 页面容器与业务内容职责混用 | 单标题与公共 Dialog 契约 | 详情/编辑/新增同视口检查 |
| 表格操作列超出背景 | 列宽和操作密度未预算 | DataTable 与 TableActions Pattern | 1280/1440px、长文案 |
| 红框删除后残留旧控件 | 历史 render/CSS 覆盖链 | 精确定位、变更影响、源码收敛 | 搜索入口/DOM/回归 |
| Tabs 切换卡死 | 可能全局重绘/重复事件 | 局部更新、状态隔离 | 连续三轮切换与日志 |
| 同名模型跨端点引用错误 | 仅用名称/局部 ID 关联 | 稳定复合键与引用契约 | 两端点同名不同版本 |
| 保存草稿污染已发布配置 | 状态边界不清 | 草稿/快照/有效态分离 | 保存、失败、回滚 |
| 执行资源 UI 删除 | UI 与业务能力混淆 | 展示与领域规则分层 | 资源治理仍有效 |

**关键教训**：先识别现有业务和设计权威，再决定组件与交互；修复必须伴随正反向回归。静态脚本语法通过无法证明浏览器交互或视觉通过。
